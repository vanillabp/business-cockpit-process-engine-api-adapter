# The memory of the deliveries is sized per adapter id, below that id

Decided on 2026-11-09 by the maintainer: what a cockpit adapter needs for its BPMS alone stands below
`vanillabp.adapters.<adapter-id>.cockpit.<key>`, and not in the cockpit's neutral tree.

This replaces decision 23 as a whole, and the sentence of decision 3 which names
`vanillabp.cockpit.process-engine-api.remembered-user-tasks`. The rest of decision 3 stays as it is.

## What was wrong

The key stood below `vanillabp.cockpit`, the tree of the settings which hold for every BPMS. It
exists only because this BPMS has no task query. So the cockpit's neutral half had to know and bind
a key of one BPMS, and this half had a check of its own for a workflow module which wrote it.

There was also one memory per node for every adapter id of this BPMS. During a migration from one
engine to another, an engine which delivers many tasks would push out the tasks of the other one.
Then the questions about those tasks would go unanswered, and the value could not be chosen per
engine.

## The decision

The key is `vanillabp.adapters.<adapter-id>.cockpit.remembered-user-tasks`, read at the adapter
and nowhere below it. Each adapter id of this BPMS gets a memory of its own, with a default of 1000
tasks each (`PeaDeliveredUserTasksOfEachAdapter`). The observer remembers a delivery in the memory of
the adapter id which delivered it, and each bridge answers from the memory of its own id.

This half binds the key itself, on both platforms (`PeaCockpitOverlayProperties`), and announces it
to the cockpit's neutral half through `PeaCockpitKeys`. The neutral half refuses the key below the
adapter, and it refuses the old place with a message which names the new one. So the own check for a
workflow module is gone.

The configuration metadata of Spring Boot has no name for "any adapter id". So no jar describes the
key for an IDE any more. `EveryKeyIsKnownToTheIdeTest` holds that no jar describes it at a wrong
place, and that each key of `PeaCockpitSettings.KEYS_READ` reaches the reading. The wiki page
"Configuration" of this half describes the key.

The old place was never a key of version 1. Only a snapshot of version 2 read it, so no upgrade guide
names it.

## Where it is referred to

- `PeaCockpitSettings`, `PeaCockpitKeys` and `PeaDeliveredUserTasksOfEachAdapter` in `core`, in their
  class comments.
- `PeaCockpitOverlayProperties`, `PeaCockpitAutoConfiguration` and `PeaCockpitBeanRegistrar` in
  `spring-boot`, and `PeaCockpitOverlayProperties` and `PeaCockpitProducer` in `quarkus/runtime`.
- `EveryKeyIsKnownToTheIdeTest` in `spring-boot`.
- `README.md`, section "Where the key stands", and entry 10 of `GAPS.md`.
- The wiki page `Configuration`.
